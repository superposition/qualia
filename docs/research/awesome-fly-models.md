## The concrete route out of Qualia's silent circuit

Qualia's current inspected configuration supplies measured visual input only to 6,091 photoreceptors, with 6,063 lacking soma coordinates. Its zero-resting spiking model and inhibitory receptor outputs do not establish descending activity. Making the simulator faster does not change that. This is local review context, not a finding about all biological fly circuits.

The best-supported visual alternative is **a separate pretrained flyvis backend**: graded dynamics with fitted resting potentials, time constants, and positive synaptic gains, retaining constrained connectivity/signs. Its methods regularize resting potentials against silence and instability. Use the complete published model/checkpoint; this does not justify arbitrary tonic current or reversing inhibitory edges. [Lappalainen et al., methods](https://www.nature.com/articles/s41586-024-07939-3).

Shiu's reference implementation instead uses resting/reset potential −52 mV, threshold −45 mV, membrane time constant 20 ms, synaptic time constant 5 ms, refractory period 2.2 ms, delay 1.8 ms, and a configurable synaptic scale. Its activation experiments apply Poisson stimulation to selected neurons. These subthreshold resting potentials do not provide spontaneous activity that would resolve an exclusively inhibitory input pathway. Copying the numeric voltages alone would therefore not repair the current problem. [Reference model.py](https://github.com/philshiu/Drosophila_brain_model/blob/main/model.py).

### Proposed implementation sequence

1. **Preserve the current model as a documented baseline.** Add a separately named graded visual-model backend, with a pinned package revision, checkpoint digest, connectivity identity, preprocessing description, and explicit output units. Do not silently reinterpret graded voltages as biological firing rates or emit invented spikes into QLSP.
2. **Use the published retinal input contract.** The custom-stimulus tutorial maps Cartesian grayscale frames through `BoxEye` to 721 hexagonal samples. Its input shape is batch × time × 1 × 721; `NetworkView(...).init_network()` loads pretrained parameters. `fade_in_state` establishes an initial state, and `simulate` returns per-neuron responses, illustrated as batch × time × 45,669. Preserve recurrent state during a live sequence and reset it explicitly after a discontinuity; do not independently warm-start every camera frame. [Custom stimuli tutorial](https://turagalab.github.io/flyvis/examples/07_flyvision_providing_custom_stimuli/).
3. **Keep camera geometry and timing explicit.** Calibrate the actual camera intrinsics, distortion, field of view, orientation, and timestamp behavior. An upstream rectangular-image resampler is not a calibration of this robot's camera. Use real luminance, preserve temporal ordering, and document any image resizing, linearization, exposure handling, or interpolation. The existing eight global columns cannot be treated as a full retinotopic image. This is the proposed robot adapter, not a demonstrated upstream integration.
4. **Validate the published computation before a motor readout.** Reproduce the chosen checkpoint's documented ON/OFF flash and directional-edge responses, then replay recorded robot video with frozen parameters. Measure response direction, latency, saturation, stability, and restart behavior. Report checkpoint variation: the paper finds different tuning clusters among trained models, so “any checkpoint” is not equivalent to a validated direction-selective circuit. [Paper, ensemble analysis](https://www.nature.com/articles/s41586-024-07939-3).
5. **Integrate nonvisual measurements without pretending they are light.** Initially retain timestamped gyro, acceleration, odometry, and lidar as explicit measured context and independent safety inputs. With calibrated camera/IMU extrinsics, gyro can predict rotational image motion for a separately declared compensation path. Odometry supplies measured ego-motion; range data can provide obstruction/TTC features. These are engineering choices requiring calibration and ablation. They are not established neuron-specific haltere, Johnston's-organ, or proprioceptive encoders in the sources reviewed.
6. **Choose an honest output boundary.** The immediate practical experiment is a small trained/calibrated readout from visual responses and measured body state to desired linear/yaw velocity, tested on recorded data and a robot-specific simulator. Label this an engineered controller. A biologically interpretable alternative requires matching visual cell types and retinal columns into MaleCNS, then studying named descending/ascending pathways with fitted dynamics. Both require work; neither is supplied by loading a connectome.
7. **Keep execution and safety separate.** Feed only validated, timestamped candidate commands to the existing fail-closed transport. Preserve hold-to-zero, deadman-from-arrival, estop behavior, and acknowledgement evidence. Motion remains prohibited until the operator's acknowledgement repair is expressly confirmed. Model output alone is not applied wheel motion.

### Exact resources to start from

The maintained installation instructions provide `flyvis download-pretrained` and `FLYVIS_ROOT_DIR`; Linux Python 3.9–3.12 is documented. These are instructions for later controlled preparation, not commands executed in this review. Pin both the package and downloaded artifact before evaluation. [flyvis installation](https://turagalab.github.io/flyvis/install/).

The official MaleCNS supplemental repository supplies `optic-column-type-assignments-v1.0.xlsx`: left/right column identifiers, L1/R7/R8 body IDs, and pale/yellow/edge/dorsal-rim column annotations. It also supplies `dnan_cluster_function_20250919.csv` for descending/ascending type clusters and sensorimotor max-flow tables. These are useful mapping and circuit-selection evidence. They do not contain the robot's camera calibration or determine neuron gains; missing IDs in the workbook must remain missing. [MaleCNS supplemental data](https://github.com/flyconnectome/2025malecns).

For whole-CNS mapping, prefer a single pinned MaleCNS brain-and-VNC reconstruction over a name-only join between a female FlyWire brain and a different animal's MANC cord. Use published type matches as type matches, not equality of individual neurons. [MaleCNS](https://male-cns.janelia.org/), [optic-lobe matching table documentation](https://github.com/flyconnectome/ol_annotations).

### Deployment on Jetson

Start with one frozen checkpoint, inference only, bounded input buffers, explicit state retention, and no ensemble at runtime. Profile complete camera-to-candidate latency, including preprocessing, transfers, evidence writes, and scheduling. Check biological integration-step rate separately from camera frame rate and wall-clock throughput. Memory use and latency on the actual Jetson remain unmeasured.

Use the PyTorch build compatible with the robot's installed JetPack/CUDA/Python combination. NVIDIA distributes Jetson-specific wheels/containers and a compatibility matrix; a desktop CUDA wheel or an MPS implementation is not evidence of ARM64 compatibility. Do not change drivers or flash the board merely to try a research package. [NVIDIA Jetson PyTorch installation](https://docs.nvidia.com/deeplearning/frameworks/install-pytorch-jetson-platform/index.html).

Flyvis uses elementwise/scatter/gather recurrent operations. Exporting it to TensorRT/ONNX, reducing precision, or rewriting kernels is a separate parity task, not an automatic optimization. First preserve a numerical reference; compare outputs and state trajectories after any accelerator change. Eon's backend comparison approach is useful here, but its desktop benchmark numbers do not establish Jetson timing. [Eon backends](https://github.com/eonsystemspbc/fly-brain).

## What remains unproven

- No reviewed source demonstrates this robot, camera, IMU/lidar suite, wheel dynamics, acknowledgement path, or safety transport operating under a validated fly controller.
- Published visual response prediction, optogenetic perturbation response, learned biomechanical locomotion, and real robot driving are different claims. Preserve this distinction in the console and evidence.
- A retina-to-MaleCNS adapter requires column/type correspondence and calibrated dynamics; missing soma positions cannot be repaired by invented anatomical locations.
- IMU/odometry/lidar feature conditioning can be useful engineering, but neuron-specific multisensory encoding needs additional experimental data and a declared model. Maintaining real input provenance does not make every mapping biologically validated.
- A trained wheel readout can establish task performance while exploiting arbitrary reservoir structure. Compare frozen published model, silenced input, shuffled/matched topology, simple non-connectome controller, and sensor ablations on held-out trajectories before attributing performance to fly circuitry.
- Neither browser demonstrations nor desktop GPU targets establish bounded Jetson latency. Benchmark the selected complete pipeline after its model contract is correct.
